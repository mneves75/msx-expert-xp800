## n8ao depth-only AO shipped (issue #1, v0.2.0-beta3)

- Implemented `docs/PERF-SPEC.md` Phases 1+2 exactly as specified (Codex lane executed,
  main session reviewed diff, re-derived artifact numbers, and judged the pose set):
  `n8ao@2.0.0` replaced NormalPass+SSAOEffect; passes are now
  `render → ao → bloom → depthOfField → lensAndTone → antialias`; `setAOEnabled` +
  `QualityProfile.ao` are the single AO mechanism; the adaptive ladder is five tiers
  with AO-off at tier 2, before any DPR cap.
- Measured (paired within-run A/B, host loadavg recorded): PostFX submissions
  159 → 39 desktop, 105 → 39 mobile; AO pair Δ 1.72 ms desktop / 1.28 ms mobile vs
  2.40 / 2.18 for the old pair; tier-2 rung saves 0.46 / 0.17 ms GPU — its real value
  is the CPU submission relief, as the spec's honest caveat predicted.
- The 7-config interleaved gpuBench showed inverted rows under host load; the trust
  rule held — only the dedicated 2-config aoPair block was quoted. profile.mjs now
  rotates config order and owns a `--lock-tier` flag for rung-position measurement.
- `applyTier` order matters: `setQuality` first, then `setAOEnabled`, so a profile
  re-application can never silently re-enable AO at tier ≥ 2.
- Gates: pnpm verify, 4 profile artifacts, 15/15 poses (perceptual pass — contacts
  grounded, no wash, no denoise splotches), verify-interactions2 20/20, autoreview
  clean (0.98), security review no findings, TruffleHog clean.
- v0.2.0-beta3 tagged and deployed to staging
  (msx-expert-xp800-staging.mvneves.workers.dev, version 7b41f71d). `verify-prod`

  passed clean on rerun with identical state checks — transient under host load
