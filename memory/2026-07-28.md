# 2026-07-28 — Foundational Findings

## Visual calibration

- A numerical probe confirmed **2.6 mm** key travel across all nine key classes. The
  reported floating keys were stale HMR state and, later, floor shading rather than
  incorrect travel.
- CRT scale became **1.16** with `z = −0.465`; the monitor dominates the composition
  without closing the rear gap.
- Bloom A/B isolated the QWERTY wash: threshold 1.0 admitted the light keys. The retained
  calibration is **threshold 1.45, intensity 0.6**, keycap roughness **0.55 fresh / 0.36
  worn**, and AgX exposure **0.72**.
- The black inset panel moved from roughly 15% albedo to `#141414`. Under the softbox the
  former value rendered gray and made the keys appear detached. A narrow occlusion band
  under the keycaps was also needed because SSAO does not reach a 2–4 mm gap reliably.
- Visual gates must respect geometry: rear poses may legitimately occlude the CRT.

## Stability and lifecycle

- The keycap spring used semi-implicit Euler with a 1/30 s clamp, above the stability
  limit `h < 0.828/ω` (**19.7 ms for ω = 42**). Simulations reached −285 mm at 40 fps and
  −157 m at 30 fps before NaN; because all 93 keycaps share one `InstancedMesh`, one
  invalid transform destroyed the keyboard. Subdividing at 1/55 s preserves the 60 fps
  result and the measured travel.
- Procedural phosphor must finish draining after power-off before sleeping.
- Reset, key, note, and joystick timers must be canceled in `dispose()`. Rebuilt modules
  must restore their interaction contracts.
- A dormant procedural screen misses cartridge changes made while WebMSX is active.
  Resume by reconciling both slots from desired state, isolating rejection per slot.

## Security and licensing

- Removing `'unsafe-inline'` from `style-src` blocks two WebMSX-injected styles but changes
  the sampled canvas by only **0.05/255** on average. The styles are unnecessary.
- Only the three CC BY 3.0 reference photographs remain committed. Four images without an
  explicit redistribution license are fetched locally for comparison.
- Rewritten Git history did not remove an orphaned object from GitHub's API by SHA. Never
  commit private material to a public repository.

## Startup performance

- Measure first with CDP profiles, long-task observation, and phase marks. Procedural
  generators use deterministic `function*` bodies with synchronous `drain` and cooperative
  ~8 ms `driveCooperatively` drivers that populate the same caches.
- `renderer.compileAsync` still performed about **270 ms** of synchronous program work.
  Staged GPU warm-up behind the boot veil reduced the measured first-use block from about
  **560 ms to 70 ms** on hardware acceleration.
- Resizing PostFX directly for warm-up left the final pass trapped at 256×144. It also
  produced falsely good performance metrics. Temporary pixel-ratio limits must use the
  normal resize path, and performance evidence is invalid if the visual gate fails.
