# 2026-07-29 — Render-on-Demand and Profiling

- `tools/profile.mjs` measures the real rAF loop with vsync disabled, interleaved A/B
  pass rounds, draw-call counters, and a CDP CPU profile. Sequential `composer.render()`
  plus `gl.finish()` produced nonphysical results under headless ANGLE/Metal because of
  thermal drift and an unreliable completion barrier.
- Baseline was **523 draw calls per presented frame**, including **94** for shadow-map
  refresh. About 70% of loop CPU time was WebGL state work; `uniformMatrix3fv` alone was
  **28.8%**.
- `SceneModule.update()` returns `false` when settled. Camera subpixel snapping and matrix
  comparison catch internal and external changes; `requestRender()` handles explicit
  invalidation, and `beforeRender()` contains work that must run only for presented
  frames. The loop stays awake for startup, resize, CRT activity, and real interaction.
- `shadowMap.autoUpdate = false`; moving or hiding shadow casters sets `needsUpdate`.
  This covers keys, cartridges, joystick, cables, controls, X-ray/wireframe changes,
  capture hiding, and context restoration.
- Removing MSAA from EffectComposer's output ping-pong buffer was byte-identical and
  avoided redundant half-float resolves. The high-quality input remains 4× MSAA.
- Adaptive quality uses the p75 of 90 presented frames. Above **22 ms** it degrades
  monotonically: high → low → 0.75× effective DPR → 0.5×. It does not promote itself,
  and automation starts locked at tier 0 for deterministic captures.
- SMAA ULTRA/HIGH/MEDIUM measured **17.38/17.68/17.39 ms**; the difference was noise, so
  ULTRA remained. The cost is the three fullscreen passes, not the preset's search loop.
- Measured 1080p results: idle tick **0.03 ms** with zero presented frames, calls
  **523→429**, submitted triangles **677k→529k**, and powered-on p95 **30.5→19.5 ms**.
  Consecutive settled captures became byte-identical because film grain no longer shifts
  without a new frame.
