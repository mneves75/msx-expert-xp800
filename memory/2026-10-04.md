# 2026-10-04 — v0.2.3 audit, fixes and release

`pnpm audit` was red at v0.2.2: ten `undici` advisories reached the dev toolchain
through wrangler → miniflare. Raising the existing override from 7.29.0 to 7.29.1
cleared them; only `undici` changed in the lockfile.

Three read-only audits (interaction/emulator, core/render, security/a11y/tooling)
produced about twenty candidates. Each shipped fix has a browser check that failed on
the old code (I24–I35, I25b, I26b, plus a URL-precedence unit test):

- WebMSX failures (offline, SRI, timeout, canvas) never reached the HUD: the screen
  pipeline was built without `onNotice`.
- The status live region and notes lived inside the console, which is `inert` and
  hidden with the mobile sheet closed and after Alt+H. They moved to the HUD root; a
  toast above the "Painel" button shows notes while the sheet is closed.
- A mouse-focused HUD button swallowed MSX typing, and Space re-activated it. Buttons
  no longer take pointer focus; a keyboard-focused button keeps only Space, Enter, Tab
  and Escape. Tab belongs to the MSX, so Alt+P now enters the panel and Esc leaves it.
- Desk contact shadows refreshed every 240 presented frames, so a cartridge moved with
  the machine off left a stale footprint. They now refresh whenever shadow casters move
  (about 0.06 ms per refresh).
- Adaptive tiers 0–2 resized the renderer, which reset the controller's best-cadence
  floor. The Engine now resizes only when the effective pixel ratio changes.
- About 24 MiB of intermediate texture height fields stayed allocated after prewarm.
- The boot message was 3.70:1 and unannounced; it is 6.17:1 with status/alert roles.
- The WebGL2 support probe kept a second live context.
- Tooling: the shared Playwright launcher impersonated third-party AI crawlers; it now
  uses Playwright's own user agent and production accepted it. `pnpm dev` binds loopback.
  `probe-game.mjs <url>` beats an exported `MSX_URL`. A favicon replaces the HTML shell
  that `/favicon.ico` used to return.

Not reproduced or deferred (see `plans/README.md`): the late `wmsx.js` double fetch
(Chrome made one request), CRT noise precision, the idle LED light cost, module
singletons, and `forceContextLoss` on HMR dispose.

Verification history: two read-only reviews (standards and spec), then an independent
behavior verifier driving Chrome and a different-model code verifier. The first round
failed on four points: focus kept after a click, toast overflow, a clamped resize, and
no keyboard route into the panel. The second round failed on a resize under a lower
ceiling. A third model review caught that the new resize check would fail under CI's
software DPR. Autoreview then found the mobile Alt+P/Esc focus return; its fix reviewed
clean.

On this workstation every Playwright headless shell exited after about 31 s, so local
proof used installed Chrome via `MSX_BROWSER_CHANNEL=chrome`. Linux CI used the bundled
shell under SwiftShader: [run 37173662195](https://github.com/mneves75/msx-expert-xp800/actions/runs/37173662195)
passed on `cee63c8` with audit, guards 3/3, keymap 93/93, textures 9/9, physics 24/24
and interactions 63/63. All fifteen capture poses matched v0.2.2 production within
dithering noise (at most 0.04% of pixels above 16/255).

`cee63c8` was tagged `v0.2.3-beta1` and deployed to staging, then tagged `v0.2.3` and
deployed to production. The deploy builds were deterministic, and all ten served files
matched the build on both targets. On staging and production, `verify-prod` passed
version 0.2.3, the strict headers, the SVG icon and real WebMSX promotion under CSP.
`probe-game` played the whole game on both, targeting the URL argument. Physical
devices, non-Apple GPUs and real screen-reader speech remain unverified.
