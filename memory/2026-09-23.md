# 2026-09-23 — v0.2.2 review and hardening

Installing failed before any gate ran: npm now marks the pinned pnpm 11.13.0 as a broken
release. The pin moved to 11.27.0, the newest 11.x outside the seven-day release-age
window. A new high `sharp`/libheif advisory (GHSA-rgj7-g3m4-5g8c) reached the dev
toolchain through wrangler → miniflare; an exact `sharp` 0.35.4 override clears
`pnpm audit` without a fourteen-release wrangler jump. Only `sharp` and its `@img/*`
binaries changed in the lockfile.

Three independent read-only reviews (security, interaction/emulator, core/HUD) produced
thirteen candidates. Each was traced in code, then proven in a browser with a check that
fails on the previous source:

- Inserting while a cartridge was still `saindo` replaced the slot's shell reference; the
  old shell stayed in the slot mouth forever (the old-code run timed out waiting for it).
- A local ROM chosen while off never reached a retained WebMSX source, because
  `appliedCartridges` still matched the wanted id.
- Power-off dropped the modifier key-up (`powerOn` is already false), so BASIC stayed
  shifted after power-on. Shift left/right also released each other's shared matrix key.
- Ejecting the last cartridge disposed the one-shot WebMSX room; the next insertion
  re-evaluated `wmsx.js`. Post-GC heap grew 19 → 31 MB over five cycles with five script
  tags; keeping the stopped bridge as the candidate holds it at 24–25 MB with one tag.
- A restored WebGL context left the PMREM environment empty. At the calibrated intensity
  (0.11) the loss is subtle (35.1 → 33.4 mean luma with IBL boosted to 1), not the
  "black scene" first claimed; the regression boosts IBL to 3 for a clear control.
- HUD pre-read ROM refusals wrote a local state copy that the next publication erased,
  and notes never reached the live region. They now go through the interaction layer.
- Side/bottom safe areas, the `svh` fallback order, and short windows (docks covered the
  title at 1280×560, off-screen below ~520 px) were fixed in CSS; the existing sheet now
  serves `max-height: 36rem`, capped at 40rem wide.

Rejected: `AdaptiveQuality.applyTier` does request frames, through
`setAdaptivePixelRatioCap` → `handleResize`; the old code already passed the proposed
check, so the change and its test were removed.

The game probe needed its "boot race" retry on 5/5 runs. The key reached WebMSX every
time; measured taps within about one second of the splash appearing are ignored by
C-BIOS, while a held key or a tap after two seconds starts the game. The probe now waits
for a stable splash plus two seconds (0 retries on 3/3). The root cause inside C-BIOS was
not isolated; users recover by pressing again.

Autoreview (P3) found duplicate Permissions-Policy features overriding earlier values;
the independent Codex verifier found `in` accepting inherited names such as
`constructor` in the CSP allowlist. Its fresh full reverify confirmed both fixed but
failed on a third hole in the same parser (`fullscreen=(*)` accepted). Rather than a
fourth patch, the guard now requires the exact Permissions-Policy string; the old
parser accepting that grant is the negative control. The verifier sandbox could not
run build, browser or audit gates (EPERM, no network); those ran locally and in CI.

[Linux CI](https://github.com/mneves75/msx-expert-xp800/actions/runs/35836527433) passed on
`71070c1e8732d457971dad02574c0bb346d9a676`, including the audit and 49/49 SwiftShader interactions. The same commit was
deployed as `v0.2.2-beta1` to staging and promoted as `v0.2.2` to production. All nine
served files are byte-identical across the build, staging and production. Both live
checks passed the strict header guard, version 0.2.2, real WebMSX promotion under CSP and
cartridge insertion; the game probe played both deployments without a retry. Physical
devices, non-Apple GPUs and a context that is lost and never restored remain unverified.
