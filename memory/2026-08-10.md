# 2026-08-10

## Page-load audit — target already met, no change shipped

- Requested loop: optimize until every page loads under 50 ms under repeatable
  conditions. Fresh baseline on the beta3 tree with the existing harness
  (`tools/bench-load.mjs`, 15 cold runs per path, viewport 1440×900, preview :4173):
  `/` load event median **25.0 ms** (p95 26.9), `/nao-existe-spa-fallback` median
  **26.8 ms** (p95 42.8). Both under 50 ms with margin, so no optimization was made —
  artifact at `.scratch/bench/beta3-baseline.json`, host loadavg ~15–21 at capture.
- The edge (workers.dev) cold-connection number (~340 ms in July's artifacts) is
  handshake-bound per the harness's own taxonomy and cannot meet 50 ms; the local
  preview tier remains the valid gate for this target.
- Scene readiness (`__msxReady` ~1.6 s) is a separate metric by design and was not in
  scope of the 50 ms gate.

## iOS Safari slow boot — shader compile dominated; parallel + deferred AO shipped

- User report "does not load on iOS" was a slow boot: on the iPhone 17 Pro simulator
  (iOS 27, localhost, cold shader cache) READY took **6.6–8.7 s**, with 73–85% spent
  compiling shaders: `warmSceneBuffers` plus the postFX per-pass warm-up (n8ao is the
  single largest program). Desktop WebKit boots the same build in 2.0–2.3 s.
- iOS WebKit exposes `KHR_parallel_shader_compile` (verified on-device). Three rounds
  via Codex lane, reviewed and measured here: (1) sliced per-module
  `compileAsync` submissions right after each registration, aggregate awaited before
  `warmSceneBuffers`; (2) postFX pass warm-up moved before that await so main-thread
  pass compiles overlap driver-side scene linking (marks renamed
  `msx:fxwarm-done`/`msx:link-done`/`msx:scenewarm-done`); (3) coarse-pointer
  non-webdriver boots skip the n8ao pass warm entirely, reveal without AO, then warm
  and re-enable it in idle after `onReady` (never at adaptive tier ≥ 2 — the ladder is
  monotone-down and must stay authoritative).
- Functional proof on the simulator overlay: `AO off@READY → ON@+0.5 s`. Regression
  proof: WebKit ready 2.04 s, 20/20 interactions, hero/keyboard/screen poses correct
  (webdriver path keeps AO in frame one for capture), bench-load unchanged (~25 ms).
- **Cold-cache magnitude on the simulator remains unproven**: parallel sessions drove
  host loadavg 7→30 and inflated even the pure-CPU module build 2.4×–6×. In the one
  matched contended window, round 2 beat baseline ~20% (30.5 vs 38.1 s). Re-measure on
  a quiet host with the erase protocol (`simctl erase` is what makes the Metal shader
  cache cold — the cache survives Safari restarts and is keyed by shader source, so
  A/B builds sharing shaders contaminate each other), or judge on a real iPhone via
  staging.
- Measurement tooling learned: `.scratch/ios-dist` carries the instrumented dist
  (probe overlay prints marks + AO trail + console warns; served by
  `python3 -m http.server`; the iOS simulator reaches the host's localhost directly).
  First `open-url` after an erase lands on Safari's start page — open twice.
