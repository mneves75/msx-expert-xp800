# Whole-codebase audit and release plan

Baseline: `3d37ce4cb5660cc7b13e7632c6a061378e3a3dbc`, `main`, package version
`0.2.0-beta7`. Existing edits add pnpm guidance to AGENTS.md and CLAUDE.md;
preserve their intent while consolidating it. Only this task's process was found
in this checkout. Production and staging are separate static-asset Workers.

## Objective and acceptance

Keep the photographic reconstruction, real keyboard/cartridge behavior, procedural
assets, local-only ROM handling, and calibrated rendering. Delete code that serves
no current caller, simplify actual boundaries, and retain performance changes only
when the real product or deterministic work counters support them. No deletion quota.

Completion requires a production build, structural lint, focused regressions,
desktop/mobile renders inspected against references, real emulator/game tests,
dependency and secret scans, independent Standards and Spec review, P3 autoreview,
verified staging and production, version tags, committed docs, and pushed changes.
Hardware outside the available browsers must be described as unverified.

## Execution sequence

1. **Inventory and baseline.** Read all source, tooling, configurations and current
   docs across three bounded read-only audit scopes plus the main session. Capture
   a desktop profile and desktop/mobile images before edits; record host load and
   effective DPR. Keep the app running on an explicitly owned port. Baseline build and lint
   already pass (two known constant GLSL interpolation warnings).
2. **Repair proof before trusting it.** Fix Playwright timeout argument placement,
   missing-subject capture acceptance, and assertions that report success without
   observing behavior. Prove guards fail with a planted negative and pass with a
   positive control. Keep behavioral assertions; remove obsolete one-off probes.
3. **Delete HUD integration scaffolding.** Replace unknown-state coercion, method
   synonym maps, discovery timers, custom-event fallback and optimistic snapshots
   with the existing typed InteractionsHandle and one subscription. Preserve UI,
   accessibility, error copy, file-size-before-read validation and capture globals.
   Verify rejected cartridge operations cannot fabricate an occupied HUD slot.
4. **Delete unused runtime paths.** Trace all callers before removing exported
   helpers, barrel files, obsolete screen adapters, texture generators used only by
   their own checks, and unreachable model variants. Preserve asynchronous abort,
   disposal and render scheduling where they implement real lifecycle requirements.
5. **Measured performance and lifecycle fixes.** Investigate profile hotspots,
   duplicate state publication, unnecessary per-frame scans, texture work and
   instanced GPU disposal. Record before/after counters; use timings only with
   comparable conditions. Recheck visual poses and original texture hashes.
6. **Security.** Audit static delivery, CSP/SRI/CDN trust, local ROM validation,
   DOM sinks, network/persistence behavior, public bundle and repository history,
   dependency advisories, CI and deploy configuration. The current nanoid override
   pins an affected version; move within its supported major and regenerate lock.
   Fix confirmed weaknesses and test their actual boundary; do not invent an auth
   service for a public static app.
7. **Agent DX and guidance.** Make AGENTS.md canonical and CLAUDE.md a short import.
   Provide frozen-install/hook/browser setup and one portable local QA entrypoint
   that owns its server and works with separate checkout ports. Keep screenshots,
   debug globals, shader health and failures inspectable. Add an appropriate CI
   browser smoke; avoid a new framework or orchestration service.
8. **Review and release.** Freeze edits, run Matt Pocock Standards and Spec reviews
   independently against this baseline and request, then P3 autoreview. Verify and
   fix actionable findings; rerun affected proof. Update version/changelog/current
   docs, commit explicit reviewed paths, push, tag the next `v0.2.0-betaN`, deploy
   staging and verify the served assets/version and flows. Promote to `v0.2.0`
   and production under the user's explicit deployment authorization; verify live.

## Alternatives challenged

| Approach | Decision and reason |
|---|---|
| Leave everything alone | Retain healthy art/math; reject for confirmed dead HUD compatibility and weak probes. |
| Rewrite the application | Reject: loses calibrated behavior and introduces unnecessary risk. |
| Add a UI framework | Reject: native DOM already serves this small fixed overlay. |
| Keep runtime duck typing | Delete where the producer is known and injected. |
| Create a generic event bus | Reject: one typed subscription already exists. |
| Delete lifecycle guards wholesale | Reject: HMR, async boot and GPU resources have real ownership obligations. |
| Move texture generation to workers | Reject absent new evidence: previous end-to-end measurement regressed readiness. |
| Replace WebGL with WebGPU | Reject: major compatibility migration without a demonstrated task need. |
| Lower visual quality/resolution | Reject as a default optimization: calibrated appearance is the product. |
| Merge every mesh | Reject blanket merging: semantic picking, animation and culling differ; measure bounded cases. |
| Add caches/automation for all checks | Reject: remove duplicated work first; keep one small runnable verification loop. |
| Focused deletion plus behavioral proof | Selected: removes unsupported assumptions while retaining the product and evidence. |

Five-year maintenance criterion: explicit ownership, few supported paths, portable
reproducible checks, and immutable release evidence age better than model-specific
rituals or a bespoke testing platform. Current model IDs belong to harness settings.

## External review basis

- [Martin Fowler: YAGNI](https://martinfowler.com/bliki/Yagni.html): remove speculative capabilities while preserving the ability to change code.
- [Brendan Gregg: performance methodology](https://www.brendangregg.com/methodology.html): diagnose the measured bottleneck before selecting an optimization.
- [Three.js: object optimization](https://threejs.org/manual/en/optimize-lots-of-objects.html) and [resource disposal](https://threejs.org/manual/en/how-to-dispose-of-objects.html): verify draw work and ownership in the installed implementation.
- [OpenAI: GPT-6 Astra guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra): concise nonconflicting instructions, explicit autonomy boundaries and proportional verification.
- [Anthropic: Fable 5.1 guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1): targeted edits, independent reads batched and preserved task context.

These are published references used to challenge the design; no personal advisor
consultation or endorsement is implied.

## Findings and results

The implementation removes unsupported HUD state adaptation, unused rendering options,
texture generators and cartridge variants, duplicate model contracts, throwaway mesh
wrappers, and eight superseded incident probes. It retains the explicit asynchronous
boot/disposal paths and calibrated rendering. Twelve alternatives above were considered;
the bounded deletion approach still best preserves the working product.

Confirmed behavior fixes include authoritative rejected-insertion state, one HUD update
per publication, cartridge rest detection at its actual detent, native control keyboard
ownership, mobile modal focus, instanced GPU disposal, and geometry-correct desk contacts.
The trajectory comparison matched all 9,360 frames; the physics regression passes 24/24.
The real GPU probe released all 36 uploaded instance attributes. Nine retained texture
hashes remain unchanged.

At the identical desktop profile pose, scene draw calls fell from 112 to 110,
frozen/full submissions from 151/245 to 149/243, and shader programs from 78 to 74.
The settled powered-off check now records zero renderer submissions in one second.
Mobile simulation measured 108 scene calls at 390×844 with effective DPR 2. Timing
samples were noisy, and the end of the desktop pass-cost run overlapped the mobile
run; no general FPS or pass-cost improvement is claimed from those timings.

Security work disabled WebMSX URL overrides, patched nanoid within major 3, and hardened
header/capture assertions with positive and negative controls. Dependency audit is clean.
ROM instrumentation confirmed size rejection before reading, header validation, literal
filename rendering, and no upload or persistence. The bundle secret scan's only finding
was the known procedural keyboard cache key; no secret was found in the inspected scope.

The final managed offline command passes lint, build, guard controls, all key mappings,
textures, physics and 43/43 interaction checks. Online verification also passes all 43
checks and actual WebMSX game play. Fifteen camera poses were captured and inspected;
the front shot exposed an overly large generic coverage threshold, which was corrected
and rechecked with a lit-front positive control and dark-front negative control.
Desktop and mobile panel interaction were inspected in a real browser.

Independent Matt Pocock Standards and Spec reviewers accepted the focused fixes and
reported no remaining actionable finding. Two P3 autoreview passes identified CSP
validator case and whitespace mismatches. Both were reproduced with real browser
inline-script controls and fixed with corresponding regression cases; the validator now
follows the [CSP ASCII parsing rules](https://www.w3.org/TR/CSP3/#parse-serialized-policy).
An independent final verifier accepted the parser after the guard suite and 34 additional
boundary assertions. Live release verification is recorded below.
Known reference-lighting mismatches are unchanged;
photographic identity and performance on physical mobile/non-Apple hardware are not
certified by these checks.

The beta8 artifact is live in staging: all nine served files match the frozen build,
and headers, emulator, game and mobile interactions pass. The first Linux CI run
exposed wall-time assumptions in the functional harness. A locally reproduced
SwiftShader run now passes 43/43 after waiting for actual animation/contact states and
CSS transition completion at a functional-only DPR of 0.25. Production promotion was
held for the repaired Linux gate.
The repaired harness also passes 43/43 online on the native GPU and its separate P3
review is scoped-clean. The original whole-diff audit was not repeated.

The next Linux run reached 42/43 and found a real low-frame-rate reset defect: a
190 ms wall timer could release the synthetic cover press before switch contact.
A real-engine pause reproduced zero resets while the held-press positive control
succeeded. Release now follows contact, with physical press/cancel/insertion ownership
preserved. The focused regression passes both cases, including ownership, cancellation
and insertion combinations. Its independent review and P3 autoreview found no actionable
issue. Managed offline and online checks and final Linux CI all pass, including 43/43
interactions.
